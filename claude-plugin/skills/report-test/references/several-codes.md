# Several codes in one request (for the main session)

One agent working through codes one after another keeps every earlier code's raw output in its context (1B_47-50 in one agent: context 456k, 46.5M read). Share what siblings have in common through **files**, and give every code **fresh agents**.

1. **Main session, cheap.** `rt doctor`; `rt start <code> --quiet` for every code (one line each: trace method, siblings, group conventions; the brief is in `brief.md`); `grep -A12 "Sibling reports"` in the briefs to group the codes by shared screen / code. A trace "found by: name only" has no screen yet: find it once for the whole set yourself (grep the menu definition for the function names; codes of one group are often tabs of one screen), rerun `rt start <code> --menu …` or `--route …`, and only if nothing matches ask how the screens are opened in the app (step 2). Pick a lead code per group (the one with the most screen; the import or detail variants follow it).
2. **Ask the user once for all codes** (step 4: account, SELECT OK, demo / UAT, decisions), then `rt login` once. Later, `rt check` logs in again by itself when the session expires (one process at a time; the others wait and reuse it).
3. **Two agents in a row per code, A then B**, all with **`subagent_type: "report-runner"`** (a short system prompt and 7 tools instead of general-purpose's whole tool set, re-read on every turn; it cannot spawn agents), `run_in_background`. One agent would carry everything it read in step 3 through every later turn (165-228k before the first check, on leads and siblings alike).
   - **A** runs steps 3, 6 and writes step 7's `checks.yaml` (or a `gen_checks.py` that writes it), runs **one** `rt check --only` on two or three representative entries to prove its selectors, then stops. It writes `handoff.txt` (at most 30 lines: the planned cases, the persons / companies with data, selectors still unsure, open points).
   - **B** starts fresh from `analysis.txt`, `handoff.txt`, `checks.yaml` and `probe.md`, and runs steps 7-10. It opens a code file again only for a `file:line` it needs.
   - The split pays when A read a lot (a lead, or a sibling with its own section or backend). A sibling that differs only by account or filter reads little: one agent runs both parts, since a B would spend about 60k re-reading the skill and the files for nothing.
4. **Order.** Lead A first. When it is done: lead B, and the siblings' A, which read the lead's `analysis.txt` and `handoff.txt`, `grep -n "^def " shared.py` (not its body), import it (`sys.path.insert(0, <lead workspace>)`), trace only what differs (their own section, their own backend; aim for under 150 lines per script). Each sibling's B follows its A and cites the lead's cases for shared behaviour.
   - **At most two agents in their check phase (B) at the same time.** Three parallel `rt check` runs doubled the time per UI entry on DEV (23 s to 54 s), so each budgeted run did half the work and needed twice the `--redo` turns. A agents don't open a browser beyond their short smoke check: run them freely.
5. **Shared files have one writer.** The lead's A creates `<lead workspace>/shared.py` (navigation, the dismiss step of a tour / banner, observation builders); the lead's B adds the builder helpers (cases every tab shares, sheet notes). Siblings import it and never edit it. No agent edits `.report-kit/rules/*` (group conventions, `environment.md`, `lessons.md`): each lists its proposals under "Proposed rules" in its summary, and the main session writes them once, at the end.
6. **Every agent prompt states only what the agent can't know** (report-runner already knows what to read, how to work and how to report): the code, its workspace, its part (A or B, and where it ends), the lead workspace (siblings), and the user's answers from step 2 verbatim: account, SELECT approval, no writes.
   - Only if `report-runner` is not available (`rt install-skill` not run): use general-purpose and add: read `SKILL.md` "Ground rules", "Token economy" and its steps; don't spawn agents; `rt check` / `rt build` with `timeout: 300000` in the foreground, never poll; Write / Edit for files; at most 40 lines at the end, with "Proposed rules".
7. Wait for the notifications, don't poll. An agent that stopped early is resumed with SendMessage, not respawned.
8. **Hand off** once: one table for all codes (path, counts, main bugs), the open questions of every agent, and the rules you wrote from their proposals.
